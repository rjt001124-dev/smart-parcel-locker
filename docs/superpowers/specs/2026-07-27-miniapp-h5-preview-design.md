# 小程序 H5 浏览器预览设计

## 目标

在保留微信小程序构建的前提下，为现有 Taro + React 前端增加 H5 浏览器构建与开发服务器。浏览器版复用现有页面、设计 Token、领域视图模型和真实 Kratos API，使首页、城市选择、附近网点、网点详情能够在普通浏览器中验收。

## 范围

- 增加 Taro H5 平台依赖与 `dev:h5`、`build:h5` 脚本。
- 保留现有 `dev:weapp`、`build:weapp`，不替换微信小程序交付物。
- 为定位能力建立平台适配层：微信端继续调用 `Taro.getLocation`，H5 端使用浏览器定位。
- H5 本地开发允许通过明确的预览配置使用上海坐标 `31.2304, 121.4737`。
- 所有站点、设备和柜格数据继续从本地 Kratos API 与 MySQL 获取，不在前端生成假业务数据。
- 提供浏览器启动说明、环境变量说明和验证命令。

## 不在本次范围

- 不重写独立 React Web 应用。
- 不改变 Go Kratos API、MySQL 表结构或 Redis 数据模型。
- 不增加登录、支付、订单、个人中心等后续业务页面。
- 不把本地预览坐标带入生产构建。

## 架构

现有 `apps/miniapp` 仍是唯一页面实现。Taro 根据构建目标输出微信小程序或 H5：

1. 页面和组件调用统一的站点 Hook。
2. 站点 Hook 调用定位适配层获取坐标。
3. 定位适配层根据平台选择微信定位或浏览器定位。
4. 仅当 H5 开发构建显式配置预览坐标时，适配层使用该坐标。
5. API 客户端始终请求真实的 `/v1/sites` 与 `/v1/sites/:id`。

## 配置

- `TARO_APP_API_BASE_URL`：浏览器和小程序共用的 API 基地址，默认 `http://127.0.0.1:8000`。
- `TARO_APP_PREVIEW_LATITUDE`、`TARO_APP_PREVIEW_LONGITUDE`：仅 H5 开发预览使用，必须同时存在才生效。
- H5 生产构建不提供预览坐标时必须请求浏览器真实定位；定位失败时显示现有“需要位置权限”状态。

预览坐标属于开发环境测试输入，不属于站点业务数据。界面显示的数据仍以 API 返回值为准。

## 页面与交互

- 浏览器默认以 375 像素移动端视口验收。
- 首页、网点列表、城市选择和网点详情保持 Figma 已确认的布局与文案。
- 浏览器定位失败时显示“需要位置权限”，点击“重新定位”再次请求权限。
- API 不可达时显示“网络连接失败”。
- 有效上海预览坐标下，应显示 MySQL 中现有的两个真实网点。

## 错误处理

- 无定位权限：`LOCATION_UNAVAILABLE`。
- API 请求失败：保留现有 API 错误码映射。
- 坐标缺失或不是有限数字：不发出附近网点请求，进入定位错误状态。
- 预览坐标只配置一个值：视为无效配置并回退到真实浏览器定位。

## 测试与验收

- 定位适配层单元测试覆盖微信定位、H5 浏览器定位、H5 预览坐标和无效配置。
- 现有微信小程序测试、类型检查和构建必须继续通过。
- 新增 H5 构建验证。
- 本地启动 API 后，通过浏览器访问 H5 地址，确认首页出现两个真实上海网点。
- 验证城市选择、网点列表和网点详情路由可访问。

## 交付结果

- 微信开发者工具仍可继续使用。
- 普通浏览器可直接打开本地 H5 地址进行页面与接口联调。
- README 或前端开发文档包含一条可复制的启动命令和访问地址。
